## Overview

Nexus is a lightweight API gateway designed for small and mid-sized teams. It turns the three most frequent microservice-governance chores — **auth, rate limiting, and observability** — into ready-to-use declarative configuration, with no heavyweight service mesh required.

## Design Goals

- **Zero-code integration**: routes are declared in YAML; the gateway auto-generates the management API
- **Low footprint**: under 120MB of memory per container, well suited to small deployments
- **Observable**: every request carries a TraceID, connecting logs, metrics, and distributed traces

## Core Implementation

### Token-bucket rate limiting & circuit breaking

The rate limiter implements a distributed token bucket with Redis + Lua, avoiding skewed local counters in clustered environments. Consecutive upstream timeouts trip the breaker; half-open probes restore it automatically:

```yaml
routes:
  - path: /api/orders/*
    upstream: order-service
    rateLimit:
      window: 1s
      max: 200
    circuitBreaker:
      errorRate: 0.5
      timeout: 10s
```

### Plugin-based request pipeline

Every capability (auth, rewriting, retries, canary routing) is a middleware on the pipeline, executed in declaration order. Writing a custom plugin takes a single hook function — the team has already built 6 business plugins on top of it.

## Results

- Replaced direct-connection architecture across 3 product lines; upstream-incidental alerts **down 60%**
- **35% lower** resident memory compared to similar Node.js gateways
- Full chaos-test coverage: node crashes, Redis jitter, and slow upstreams all have fallback paths

## Reflections

The core competitive advantage of a gateway is reliability. This project trained me to write failure-injection test cases *before* writing the feature code.
