## Overview

The biggest flow-breaker when driving Claude Code: switch back to the terminal, find the y/n prompt, hit enter, switch back. This project replaces permission confirmations, questions, turn completion, plan readiness, API failures, and subagent events with **native GUI dialogs** — popping up on the screen you're actually looking at. Glance, decide, keep working.

Built on Python 3.10+ with the standard-library tkinter — **zero third-party dependencies**, working across Windows, macOS, and Linux. Requires Claude Code 2.1.300+.

## Event Mapping

| Hook event | Interaction |
| --- | --- |
| `PermissionRequest` | Allow / Deny dialog with session / project / global suggestion buttons and number-key shortcuts |
| `AskUserQuestion` | Native option dialog: single or multi select, plus multi-line free-text "Other" |
| `Stop` | Task-complete notification, auto-closes in 8s; says when background work keeps running |
| `ExitPlanMode` | Topmost "plan ready" notice, auto-closes in 25s |
| `StopFailure` | Messagebox when a turn ends due to rate limit, auth, or other API errors |
| `Notification` | Messagebox when a subagent needs input or finishes |

## Engineering Details

- **Protocol parsing**: consumes the hook JSON Claude Code pipes in via stdin and renders session, tool, and project context into the dialog
- **Bilingual UI**: follows the system language; `CLAUDE_GUI_HOOKS_LANG=zh|en` overrides it
- **No console flash**: launches via `pythonw` on Windows (`python3` fallback elsewhere), so dialogs never drag a black terminal window along
- **One dialog at a time**: all dialogs share a cross-process lock; permission / question dialogs queue, and background notifications are skipped while a dialog is open
- **Async notifications**: Stop, StopFailure, plan, and subagent dialogs run in the background and never delay Claude
- **Headless-safe**: dialogs are skipped in CI or with `CLAUDE_GUI_HOOKS_DISABLE=1`, leaving Claude Code's normal flow untouched
- **Never blocks on failure**: broken hooks fall through (`onFailure: "continue"`) instead of blocking a tool call
- **Keyboard-first**: Enter to allow, Escape to deny, number keys for suggestions, Ctrl+Enter to confirm text areas — the mouse stays untouched

## Distribution

- **Plugin marketplace (recommended)**: `claude plugin marketplace add BaixuanZhu/claude-code-hooks`, then install `desktop-dialogs@claude-code-hooks`; supports `claude plugin update` and clean uninstall
- **PowerShell one-liner**: downloads all six scripts and merges exec-form entries into `settings.json` idempotently — safe to re-run
- **AI-assisted install**: the repo ships a `SKILL.md`; hand the URL to Claude Code and it installs itself

## Reflection

A small tool done right is "zero dependencies" — the standard library carries the entire GUI, so any machine with Python can run it as-is. After v0.4 grew notifications into a full interaction layer, two things became clear: **hooks are the sanctioned way to customize Claude Code deeply**, and serialized dialogs plus headless fallbacks are what let a tool like this stay in the workflow long-term.
