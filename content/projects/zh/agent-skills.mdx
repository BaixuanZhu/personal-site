## 项目概述

AI 编码助手在中文 Java 团队有些水土不服：训练语料偏英文生态，不知道团队约定俗成的边界规则，不熟悉 Sa-Token / MyBatis-Plus 的惯用法，写出的代码「能跑但不地道」。

这个项目把工程规范做成 **AI 可安装、可执行的知识**：10 个 Agent 技能按 6 个插件组织，覆盖编码契约、单元与集成测试、主流框架开发、MQ 可靠性与敏捷流程；支持 Claude Code 插件和 `npx skills` 两种安装方式，后者适配 Cursor / Codex / Zed 等 41+ AI 编码工具。

## 分层设计

- **通用底座**：`java-contract` 读 `pom.xml` 确定目标 JDK，把八项边界决策落成项目规则文件；`java-unit-test` 关注开发期纯单测，识别「绿灯但没测到」；`java-integration-test` 处理集成测试的三项决策与三种假绿机制
- **框架增强**：`sa-token-dev` 覆盖登录鉴权、SSO、JWT 与会话；`mybatis-plus-dev` 覆盖 CRUD、分页、事务与逻辑删除，并带项目播种机制；`mq-reliability` 用基线实测驱动 RabbitMQ 可靠性契约
- **敏捷流程**：`using-agile` 作为入口，按项目阶段路由到 `agile-strategic`（愿景 + C4 + ADR）、`agile-backlog`（待办）与 `agile-sprint`（Sprint 规划）；待办真源是 `backlog.json`

## 规范的知识化

以 `java-contract` 为例：技能不会把整本手册塞进上下文，而是读 `pom.xml` 确认目标 JDK，再把「方法返回 null 还是空集合」「异常如何向上抛」这类边界决策落成 `.claude/rules/java-contract.md`。它用前主动读一次，写完编译验证，并附按失效模式追问的存量审查七组。

规范的价值不在于写得多全，而在于 **AI 在什么时机需要哪一条**。触发描述写得含糊，再好的内容也不会被加载；内容写得冗长，又会挤占宝贵的上下文窗口。

## 工程化维护

- `skills/` 是唯一内容源；`plugins/` 是为 Claude Code / ZCode 插件规范准备的镜像，由 pre-commit hook（`scripts/sync-plugins.mjs`）自动同步，GitHub Actions 兜底校验 —— **改技能只改一处**
- 双通道分发：Claude Code 插件（托管只读、随插件更新）与 `npx skills`（复制可编辑副本到项目，灵活但需自己跟进更新）
- 敏捷套件附带三个 hook：按项目当前阶段每轮注入「下一步该做什么 + 这步最容易漏的铁律」，写 `backlog.json` 后自动校验结构并重渲染 Sprint 点数

## 评测驱动

每个技能的**达尔文评估产物** —— 测试 prompt、产出快照、判分记录 —— 全部公开在 `eval/` 目录，按技能分子目录，任何人可以查看与复现。技能的质量不靠「感觉不错」，靠可回归的评测。

## 反思

写技能最难的不是堆规则，而是决定「**AI 在什么时机需要什么上下文**」。这次重构把早期按「知识门类」拆分的技能收敛成按「工作阶段」组织：先立契约，再写测试，再做框架开发，最后进入敏捷流程。技能设计本质上是信息架构问题，而不是 prompt 模板问题。
