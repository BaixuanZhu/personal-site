## 项目概述

Nexus 是一个为中小团队设计的轻量级 API 网关。它把团队在微服务治理中最高频的三件事——**鉴权、限流、可观测**——做成开箱即用的声明式配置，不需要引入重量级的服务网格。

## 设计目标

- **零代码接入**：路由规则用 YAML 声明，网关自动生成管理 API
- **低资源**：单容器内存占用低于 120MB，适合小规模部署
- **可观测**：每个请求自动携带 TraceID，打通日志、指标与链路追踪

## 核心实现

### 令牌桶限流与熔断

限流器基于 Redis + Lua 实现分布式令牌桶，避免集群环境下本地计数不准的问题；下游连续超时自动熔断，半开状态下探测恢复：

```yaml
routes:
  - path: /api/orders/*
    upstream: order-service
    rateLimit:
      window: 1s
      max: 200
    circuitBreaker:
      errorRate: 0.5
      timeout: 10s
```

### 插件化的请求管线

所有能力（鉴权、改写、重试、灰度）都是管线上的中间件，按声明顺序执行。编写一个自定义插件只需要实现一个钩子函数，团队内部已用它扩展出 6 个业务插件。

## 项目成果

- 在公司 3 条业务线替换了直连架构，上游服务异常导致的告警 **减少 60%**
- 与同类 Node.js 网关方案相比，常驻内存 **降低 35%**
- 完整的 Chaos 测试覆盖：节点宕机、Redis 抖动、下游慢调用均有兜底路径

## 反思

网关类项目的核心竞争力是「稳」。这个项目让我养成了先写故障注入用例、再写功能代码的习惯。
