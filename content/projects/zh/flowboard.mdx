## 项目概述

FlowBoard 是一个面向远程团队的实时协作白板。团队成员可以在无限画布上共同绘制流程图、便签与原型草图，所有操作毫秒级同步，断网后重新连线自动合并编辑内容。

项目从零到一由我独立完成，覆盖前端渲染引擎、实时同步协议与服务端集群部署，目前已在三个创业团队中日常使用。

## 核心技术挑战

### 1. 冲突自由的多人编辑

采用 **CRDT（无冲突复制数据类型）** 作为协同内核，为每个画布元素维护逻辑时钟，保证任意编辑顺序最终收敛到一致状态：

- 元素级合并粒度，两人同时移动同一图形不会互相覆盖
- 增量同步只传输差量操作，单次报文平均仅 320 字节
- IndexedDB 持久化操作日志，离线 8 小时的编辑仍可无损合并

### 2. 高性能画布渲染

自研 Canvas 渲染管线，针对大规模元素场景做了分层优化：

| 优化手段 | 效果 |
| --- | --- |
| 静态元素离屏缓存 | 重绘耗时下降 70% |
| 视口裁剪与四叉树索引 | 万级元素下交互仍保持 60fps |
| requestAnimationFrame 批量提交 | 高频拖拽不造成事件阻塞 |

### 3. 弹性的服务端架构

```typescript
// 房间状态通过 Redis Pub/Sub 跨节点广播，
// 单个 WebSocket 节点只持有它负责的房间
await redis.publish(`room:${roomId}`, encode(ops));
```

网关层按房间哈希分发连接，节点故障时客户端自动重连并从快照恢复，全程用户无感知。

## 项目成果

- 压测环境下支撑 **10k+ 并发在线编辑**，P99 同步延迟低于 50ms
- 首屏加载通过代码分割与资源预取优化，较初版 **提升 40%**
- 开源后在社区获得 1.2k Star，收到 4 位外部贡献者的 PR

## 反思

> 实时协同的难点不在协议本身，而在于把「最终一致」的抽象正确地暴露给 UI 层——让用户永远看不到合并过程，是整个项目最花时间打磨的部分。

下一步计划引入 WebTransport 进一步降低弱网环境下的同步延迟。
